# Karpathy Guidelines Patterns

用于 `karpathy-guidelines` 的代码任务行为约束 reference。

## 适用场景

- 代码实现前的假设澄清与成功条件定义
- cleanup / refactor 时控制改动范围
- bugfix / feature 完成前的验证收口

## 推荐模板

```text
假设/边界：只处理用户请求中的问题，不扩展相邻重构。
最小方案：先复现或定位现有覆盖，再做最小补丁。
改动范围：仅触达直接相关文件；删除本次改动制造的 unused。
验证方式：运行目标测试、cargo check 或等价静态检查。
剩余风险：列出未覆盖的环境、外部服务或集成面。
```

## 常见错误

```text
❌ 借修 bug 机会重写整个模块
❌ 为单个调用点抽象出通用框架
❌ 没有验证输出就说完成
```

## 正确做法

```text
✅ 最小可行补丁优先
✅ 每个改动行都能追溯到用户请求
✅ 用可复现命令或明确证据支撑完成声明
```
