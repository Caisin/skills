# 角色创建者

为 KX 管理端创建可安装、可复制、可审计的角色。角色不是一组 API code 前缀，而是操作者完成页面工作流所需的最小权限闭包。

## 适用边界

### 适用

- 新增内置角色或角色模板，并通过 data migration 安装到已有数据库
- 区分页面读取、按钮动作、弹窗/Drawer 查询和提交接口
- 创建管理角色与真实只读角色
- 增加角色复制 API 和管理端复制入口
- 审计 `au_role_perm`、`au_role_api` 与 `au_api_perm` 的最终授权

### 不适用

- 用户数据范围、租户隔离或资源所有权规则：交给对应业务 service
- 新增业务页面、DTO 或领域 API 本身：使用 `write-ctl` / `write-svc`
- 非平凡权限模型或安全边界尚未确定：先使用 `kx-design`

## Reference Selection

- 创建、复制或审计角色
  - 读 `references/patterns.md`
- 涉及管理端按钮、弹窗和操作闭环
  - 同时使用 `admin-operator-ux`
- 新增迁移和测试
  - 同时使用 `write-tests`；数据库测试按目标 crate 使用 `database-tests`

## 执行流程

1. 从产品宿主的完整 `ApiCatalog` 和权限种子核实角色落点，不按文件名或 API 前缀猜测。
2. 沿前端页面逐项记录：页面初始化 API、详情 API、按钮 API、弹窗/Drawer 打开 API、提交 API、共享选择器 API。
3. 建立“角色 -> 页面 -> 按钮 -> API -> 允许/拒绝”的权限矩阵，并为只读角色列出代表性拒绝集合。
4. 页面权限只绑定加载与只读 API；混合读写的 API 家族使用精确 code，写 API 归按钮权限。
5. 公共或 `auth_only` API 不重复写入角色授权；跨模块弹窗依赖的受保护 API 必须绑定到打开该弹窗所需的页面或按钮。
6. 新角色通过前向 data migration 安装。迁移先确保 API catalog 和权限节点存在，再写角色与授权；已有绑定需要收窄时显式删除旧 `au_api_perm`，因为增量同步只新增、不删除。
7. 角色复制在 Auth 单库事务中复制角色设置、直接权限和直接 API；新编码必须唯一，复制后不影响源角色与现有用户绑定。
8. 前端所有动作使用与按钮权限一致的 auth code。没有权限时不展示可执行入口；后端仍必须拒绝绕过前端的调用。
9. 用 SQLite 验证角色可见页面、可用弹窗接口、允许动作、代表性拒绝动作，以及复制后的授权集合完全一致。

## 核心规则

1. **权限闭包**：页面能打开不等于角色可用，弹窗加载和保存 API 都属于功能权限。
2. **只读可证明**：只读角色必须对写 API 有后端拒绝测试，不能只靠隐藏按钮。
3. **页面不吞写权限**：菜单权限不得用覆盖写 API 的宽泛通配符。
4. **按钮与 API 同源**：前端 auth code、`PermissionSeedSpec::button` 和 API patterns 必须表达同一动作。
5. **父目录自动补齐**：只直接授予目标页面/按钮；菜单树展示所需父目录由权限加载补齐，避免父目录宽泛 API 绑定扩大权限。
6. **角色不替代数据权限**：角色决定能否调用接口，service 仍按 UID、组织、号码组等范围过滤数据。
7. **复制是快照**：复制创建独立角色，不与源角色建立后续联动。
8. **迁移可重复验证**：首次安装与已有数据库前向升级都必须得到相同权限闭包。

## 常见错误 vs 正确做法

```text
❌ 给只读页面绑定 msg.device.*，再靠前端隐藏保存按钮
❌ 只授予菜单和提交 API，遗漏弹窗初始化、详情、选项集 API
❌ 直接授予父目录，意外获得同目录其它页面 API
❌ 修改 PermissionSeedSpec 后只跑增量同步，误以为旧绑定会自动删除
❌ 复制角色时先创建再逐表写授权，失败后留下半成品
✅ 页面绑定精确读 API，按钮绑定写 API及其弹窗依赖
✅ 用有效 API 授权正反例证明管理角色和只读角色边界
✅ 在单库事务中复制角色本体、permission_ids 和 api_ids
```

## 输出模板

```text
角色与首页
页面/按钮/API 权限矩阵
公共与弹窗依赖
迁移与兼容
复制语义
正反向验证证据
```

## 完整示例

**Input**

```text
给库存模块创建管理员和只读角色，并支持从现有角色复制后调整。
```

**Output direction**

```text
- 先审计库存页面初始化、详情、编辑弹窗和选择器 API。
- 把菜单权限收窄为查询 API，把新增、编辑、删除、同步拆到按钮权限。
- 用前向迁移创建 inventory_admin / inventory_readonly，首页指向库存概览。
- 新增事务化角色复制接口与受权限控制的复制弹窗。
- 测试只读角色允许列表/详情并拒绝所有代表性写 API，复制角色的直接授权与源角色一致。
```
