# 后台操作者体验

目标是让操作者快速识别对象、就地完成动作、明确知道结果。

## Reference Selection

- 布局、表格、表单和关联维护：`references/patterns.md`
- 稳定用户反馈的沉淀规则：`references/evolution.md`

## 执行流程

1. 明确操作者、主任务、数量、风险和最容易出错的步骤。
2. 核对页面控件到 handler、弹层、API、权限、保存刷新和失败反馈的完整链路。
3. 列表优先展示对象识别、状态和下一步；技术字段进详情，常用字段可就地维护。
4. 多字段表单按业务分块；独立生命周期的数据用 Tab/Drawer 和独立 API，不塞回主对象。
5. 用组件测试或浏览器验证“定位对象 -> 操作 -> 保存 -> 刷新 -> 再次确认”。

## 核心规则

- 操作列只保留高频动作；字段本身可作为维护入口。
- 弹层层级、遮罩和焦点必须正确；关闭后保留筛选、页码和上下文。
- 排序、筛选、全文搜索、导出和权限必须有真实后端契约。
- 关联号码、用户、角色等多项数据用可分页表格维护，多选框只负责添加。
- 批量任务走持久化任务中心，展示进度、成功/失败数、逐条原因和结果文件。
- 引用选择器提供可用的新增/刷新/维护入口；新增完成自动回填。
- 业务表单不暴露原始 JSON、文件 ID 或其它纯技术字段。
- 管理员与普通用户的数据范围由后端判定，前端隐藏不能替代授权。

## Skill 演进

可跨页面复用的稳定反馈才写入 `evolution.md`、规则和 eval；一次性产品要求留在业务代码或设计文档。
