# 后台操作者体验演进记录

本文件记录能演进 `admin-operator-ux` 的稳定反馈。只保留匿名化、可复用的模式，不记录业务敏感值、个人路径和一次性像素参数。

## 更新流程

每次收到新的操作者反馈：

1. 记录反馈表达的操作阻力和发生上下文。
2. 标明它修正了哪条现有规则，或为何需要新增规则。
3. 判断适用范围：单页面、同类页面、所有后台页面。
4. 将稳定规则写入 `SKILL.md` 或 `patterns.md`。
5. 新增一个正向 eval；存在误用风险时再新增一个边界 eval。
6. 运行 repo-local skill 全量校验。

## 规则晋升门槛

满足任一条件可晋升为稳定规则：

- 用户明确要求形成规范或以后统一遵守；
- 同类问题在两个以上页面出现；
- 问题会造成越权、数据错误、任务丢失或页面不可用；
- 明显影响后台高频任务的完成时间和错误率。

单产品术语、偶发特殊流程和视觉微调保留在业务设计或代码中，不提升为通用 skill 规则。

## 变更记录

### 2026-09-03：多关联项从长多选框改为分页维护表

来源反馈：分组关联的号码和用户增多后，纯多选下拉难以查看、定位和删除，操作列又重复提供了已有字段入口。

提炼结果：

- 关联项主维护面使用分页表格，稳定展示识别字段和逐项移除动作。
- 选择器只出现在独立“添加”弹层中，添加完成后回到表格并刷新。
- 数量列已经提供维护入口时，操作列不再重复放同一动作。
- 关联增删应明确是立即持久化还是统一保存，不能让操作者猜测。

### 2026-09-03：嵌套弹层必须显式校验显示层级

来源反馈：从详情 Drawer 点击编辑后，编辑 Modal 实际渲染在详情层下面，入口和 handler 都存在但操作不可用。

提炼结果：

- 从 Drawer 或 Modal 打开的子弹层必须高于父弹层，不能只依赖组件默认层级或 DOM 顺序。
- 同时校验遮罩、焦点和关闭顺序；关闭子弹层后应回到父对象上下文。
- 静态审查只能证明显式层级配置存在，最终可见性仍需组件测试或浏览器点验。

### 2026-08-31：业务表单不暴露原始 JSON

来源反馈：测试消息弹框把扩展 payload 作为 JSON 交给操作者填写，字段含义、可用键和校验边界都不清楚，增加了误填和泄露敏感信息的风险。

提炼结果：

- 普通后台表单必须把稳定 payload 字段转换为有业务名称和校验的控件。
- 无法定义稳定语义的未知键不进入普通表单，不能用“高级参数”把协议复杂度转嫁给操作者。
- 只有面向技术运维且确实需要任意结构时，才允许使用明确标注风险的专家模式 JSON 编辑器。
- 编辑重发只恢复当前受支持字段，不自动回填或再次发送历史未知键和敏感字段。

### 2026-08-30：引用选择器全宽并将刷新收为 suffix

来源反馈：引用选择器的主输入区域被刷新按钮挤窄；同类组件需要统一布局，同时较长的配置步骤不应默认占据首屏。

提炼结果：

- 引用选择器占满字段剩余宽度，刷新按钮紧贴右侧作为 suffix。
- 同构的凭证、Provider、SIM 卡等公共选择器统一复用该布局，不逐页复制样式。
- 多步骤配置指引默认折叠，标题和展开入口常显，步骤与相关链接一起展开。
- 折叠开关保留键盘操作和 `aria-expanded`，即时校验提示不进入折叠内容。

### 2026-08-30：快捷新增弹窗与完整维护入口分层

来源反馈：引用选择器把“新增”和“前往维护页面”并列放在字段旁，导致常用新增仍要离开当前任务上下文。

提炼结果：

- 字段旁的新增按钮必须直接在当前页面打开快捷新增弹窗。
- 完整维护页面的跳转放在快捷新增弹窗内，不与新增按钮并列展示。
- 快捷新增只覆盖常用字段；复杂编辑继续进入专门维护页。
- 新增成功后自动选中新记录并刷新选项，保留父表单其它输入。
- 视觉上优先把“新增”放入下拉面板底部，字段旁只保留刷新按钮，避免操作区拥挤。

### 2026-08-30：Provider 引用必须可维护或明确只读来源

来源反馈：消息通道表单的 Provider 下拉框没有告诉操作者去哪里新增配置，也没有刷新入口；消息测试台的通道和推送端点选项同样容易过期。

提炼结果：

- Provider 选择器旁必须提供快捷新增和刷新；完整维护页面的跳转放在新增弹窗内。
- 刷新后保留当前表单上下文，不能要求关闭弹框重来。
- 没有后台写 API 的引用（例如 App/小程序上报的推送端点）必须明确标记为只读来源，只提供刷新，不伪造新增入口。
- 审核时要逐项核对下拉数据的来源、维护权限、跳转路由和刷新闭环。

### 2026-08-29：用户第一性与必要的破坏性重构

来源反馈：界面应以使用者完成任务的最短路径为第一性原则，关联数据要在附近直接操作；当旧页面或表设计阻碍清晰操作时，可以重构，而不是继续堆叠兼容补丁。

提炼结果：

- 把最短路径、单一语义、数据分层、关联处直达、最小操作和 Tab 分层提升为跨后台页面规则。
- 前端不得为了一个用户动作串联多个有副作用的 API；需要时新增后端事务/聚合接口。
- 重复弹框、详情和状态反馈收敛到公共组件，同时保留权限与影响范围。
- 破坏性重构只有在旧模型导致数据错误、越权、任务丢失或持续阻碍操作时才采用，并要求迁移边界、回归测试和二次复审。

### 2026-08-28：跨业务导入导出共用一个历史页面

来源反馈：多个业务都需要查看历史文件，但没有必要为每个业务分别建立导入记录页面。

提炼结果：

- 共用同一运行模型的导入导出记录统一进入一个公共历史页面。
- 公共页按业务定义、方向和状态筛选，并统一提供原文件、结果和错误明细下载。
- 业务页面只保留任务发起入口或公共历史跳转，不复制记录表、API 和历史弹窗。
- 业务专属逐项恢复明细可以保留在业务表中，但不因此复制历史页面。

### 2026-08-28：共享秘密使用可复用凭证

来源反馈：多个开发者账户可能使用同一个密码；账号已保存在业务账户记录中，没有必要为每个账户创建一份账号密码凭证。

提炼结果：

- 区分业务对象标识和可共享秘密的所有权。
- 业务表已保存账号时，凭证选择器可同时提供纯密码与账号密码类型，并优先现场创建纯密码凭证。
- 服务端按业务允许列表校验凭证类型，不能放宽为任意凭证。
- 多个业务对象可以引用同一凭证 code，不复制相同秘密。

### 2026-08-28：引用型下拉补齐新增、维护和刷新闭环

来源反馈：选择凭证等独立主数据时，需要能直接新增或进入管理页，并在返回后刷新下拉选项继续当前表单。

提炼结果：

- 引用字段只保存稳定 ID/code，不再让操作者手填技术编码。
- 下拉框旁提供新增或维护入口以及刷新按钮。
- 新增/维护后的选项重载不应清空当前表单上下文。
- 服务端继续验证引用对象的类型和可用状态。

### 2026-08-28：将交互闭环纳入功能完整性验收

来源反馈：评审后台页面时不能只看页面和控件是否存在；需要实际核对点击按钮后弹层是否打开、操作是否连贯，以及业务动作是否缺失。

提炼结果：

- 新增“交互必须闭环”核心规则。
- 要求按“入口 -> handler -> 弹层/路由 -> 提交 -> API -> 刷新/反馈”留存证据。
- 静态代码审计不能替代组件测试或浏览器点验；未实际触发的动态行为明确标为待验证。
- 按操作者任务核对缺失的编辑、删除、审核、批量、导入导出、撤销和重试等动作。

### 2026-08-28：建立初始操作者规则

来源反馈：表格空间有限时不要堆操作按钮；维护某项数据应从对应字段进入；多字段表单应按相关性分块；复杂关联数据应在同一对象上下文内通过 Tab 维护。

提炼结果：

- 增加“字段即入口”和“动作聚焦”规则。
- 增加列表信息分级、表单分块和关联数据 Tab 模式。
- 增加前后端排序、权限、异步任务必须真实打通的验收要求。
- 要求后续稳定反馈同步更新规则、reference 和 eval。

## 常见错误

```text
❌ 收到一次像素调整就修改通用规则
❌ 只记录反馈，不更新对应 eval
❌ 新旧规则冲突时全部保留，导致执行方向不确定
```

## 正确做法

```text
✅ 只晋升明确、重复、高风险或可跨页面复用的反馈
✅ 同步更新规则、模式、演进记录和 eval
✅ 用替代说明移除过时规则，并运行全量校验
```
